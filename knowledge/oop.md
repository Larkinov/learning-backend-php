### Lazy Loading

Применение и принцип работы:

- Паттерн применяется тогда, когда загрузка данных необходима только после применения некоторых действий или триггеров, а не вместе с инициализацией основных скриптов. После загрузки данные сохраняются в переменной и выдаются по мере необходимости. Например: когда открывается страница интернет-магазина, загружаются лишь те данные, которые находятся на экране устройства (или чуть ниже), а не все данные сразу. Или когда сохраняется роль пользователя и затем эта роль выдается в тех местах где она нужна, а не загружается каждый раз.
- Принцип работы: данные загружаются в определенной функции, а не при инициализации объекта класса, то есть их загрузка начинается тогда, когда это необходимо. Результат сохраняется внутри класса/функции.

В виде класса

```php
class Roles
{
static $roles;

    public static function roles()
    {
        if (null !== static::$roles) {
            /** здесь как-то загружаются $roles из БД ... */
            static::$roles = $roles;
        }
        return static::$roles;
    }

    public static function isAdmin()
    {
        return in_array('admin', static::roles());
    }

}
```

В виде функции

```php
//функция возвращающая роли юзера
function roles()
{
    static $roles;
    if (null !== $roles) {
        /\*_ здесь как-то загружаются $roles из БД ... _/
    }
    return $roles;
}
```


### Шаблонный метод

Если разным объектам необходимо выполнять один и тот же метод, но по-разному:
1. Создать родительский абстрактный класс.
2. (Если необходимо создать общие методы)
3. Создать абстрактный метод.
4. Реализовать его в дочерний классах.

### Стратегия

Если есть какой-то алгоритм действий, а реализация действий может быть разной:
1. Создать интерфейс действия. Добавить метод.
2. В методе, который выполняет этот алгоритм, принимать на вход типы объектов этого интерфейса.
3. Создать различные классы которые реализуют данный интерфейс.

### Декоратор

Если есть какой-то базовый объект и необходимо добавить к нему надстройку:
1. Создать интерфейс.
2. Реализовать метод интерфейса в базовом классе.
3. Наследоваться от базового класса, реализовывая метод интерфейса и в нем, выполнять надстройк, а затем вызывать родительский метод.

### Фабрика / Абстрактная фабрика
Если есть иерархия объект одного типа:
1. Создать интерфейс который будет создавать один из подтипов
2. Реализовать этот метод в классе Фабрики.
3. В методе в котором нужно создавать эти объекты, передать интерфейс


### Наблюдатель
Если у некоторых объектов есть зависимость от каких-то событий:
1. Создать интерфейс наблюдателя (подписка, отписка, уведомление)
2. Реализовать его.
3. Создать класс события.
4. Создать интерфейс подписчиков, создать метод update, который принимает тип события.
5. Реализовать метод update в классах, которые зависят от события
6. В инициализации проекта подписать зависимые класса к классу наблюдателя.
7. В местах возникновения события вызывать метод update

### Строитель
Если необходимо собирать какой-то объект или задачу, и чаще всего объект/задача может собираться по-разному

### Компоновщик
Если необходимо рассматривать структуру объектов как единый объект и вызывать единый метод:
1. Создать интерфейс с методом единым для всей структуры
2. Во "внешнем/родительском/сборщике" классе реализовать этот метод - вызвать необходимые действия, затем пройтись циклом по "внутренним" элементам и вызывая метод интерфейса
4. В классах которые являются "внутренними" реализовать интерфейс.

### Контейнер зависимостей
Поголовная панацея всех фреймворков - создание зависимостей в "автоматическом" режиме. Чаще всего через рефлексию. Проще использовать готовые решения
